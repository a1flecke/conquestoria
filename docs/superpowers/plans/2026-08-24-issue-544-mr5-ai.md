**Goal:** Give AI-controlled civilizations full mechanical parity with the
human player for Great Generals (MR3/MR4): AI civs must actually acquire
Generals, and once they have one, must evaluate and issue Rally, Seize the
Moment, and Last Stand through ability-specific evaluators feeding a shared
spend layer, plus extend existing tactical AI with supply-aware unit-safety
judgment. Per contract §"AI / hot-seat / saves" items 80-84 and repo-mapping
doc §10's MR5 description ("supply-aware AI unit-safety scoring, General
ability evaluators (Rally/Seize/Last Stand), difficulty-scaled judgment
only").

**Drift/prereq findings (verified against current code, not assumed from the
spec — see `.claude/rules/spec-fidelity.md`):**

1. `checkAndQueueGeneralCandidateChoice` is called from `turn-manager.ts` only
   `if (civ.isHuman)` (line ~845). **AI civs currently never queue a General
   candidate choice, and therefore never spawn a General at all** — the
   `generalProgress` counter accumulates for them but nothing ever reads it.
   The comment there explicitly defers this: "AI eligibility/spawning is
   MR5's scope, not MR3's." This is MR5's first blocking prerequisite.
2. No file under `src/ai/` references `great_general`, `generalDefinitionId`,
   `HeroicAbilityId`, or any export from `great-general-abilities.ts`. The AI
   has zero awareness of Generals today.
3. `great_general` is classified `['civilian']` in `UNIT_CLASS_BY_TYPE`, and
   `AIStrategicRole` (the enum the plan/assignment system in
   `ai-unit-assignment.ts` dispatches units by) has no role a General could
   ever fulfill. **A General owned by an AI civ is never assigned to any
   plan and never reaches `rankUnitTacticalActions`/`chooseTacticalSequence`
   at all** — it just sits at the capital forever. This rules out bolting
   ability evaluators onto the existing plan/role tactical-action system
   (`ai-tactics.ts`'s `AITacticalAction` union); Generals need their own,
   separate per-civ dispatch step, matching contract's "ability-specific
   evaluators feeding a shared spend layer" framing (this reads as a
   dedicated decision module, not a `rank*` extension).
4. The passive stabilization aura (`getPassiveStabilizationTargets`) is
   **already** wired civ-agnostically into `supply-progression.ts`/
   `supply-system.ts` — it runs automatically for every civ's Generals,
   human or AI, with no AI-specific code needed. Nothing to do here.
5. `getHeroicCommandEligibility`/`issueRally`/`getSeizeTheMomentEligibleUnits`/
   `issueSeizeTheMoment`/`getLastStandPreview`/`issueLastStand` are all pure,
   state-in/state-out, and MR4-proven difficulty-invariant (see
   `tests/systems/great-general-mr4-invariants.test.ts`). MR5 only needs to
   decide *when* to call them and *with what arguments* — no new ability
   mechanics, no changes to `great-general-abilities.ts` itself.
6. `rankWithdrawals` (`ai-tactics.ts:272`) is the AI's one existing
   unit-safety judgment call — gated purely on
   `unit.health < profile.retreatHealthPercent`. It has no awareness of
   `Unit.landSupply` at all. This is the concrete extension point for
   "supply-aware AI unit-safety scoring."
7. `OPPONENT_CHALLENGE_PROFILES` (`src/core/opponent-challenge.ts`) already
   has an established convention for difficulty-scaled *eagerness/weight*
   knobs that never change eligibility or mechanics — e.g.
   `submarineEscortWeight`, `pillageAggressivenessMultiplier`,
   `crisisDispatchWeight`. New General-command knobs must follow this exact
   pattern (a multiplier consumed by a score, never a branch on
   `opponentChallenge` inside an eligibility function).
8. `processNonHumanMajorRound` in `ai-round-scheduler.ts` is the real
   per-civ-per-round AI entry point (`turn-manager.ts` never imports from
   `src/ai/*`, confirming the existing layering: `src/core/turn-manager.ts`
   is civ-agnostic bookkeeping, all AI *decision-making* lives under
   `src/ai/`). The new General-command step is added here, not in
   `turn-manager.ts`.

**Architecture:** A new `src/ai/ai-general-command.ts` module owns all
AI-side General decision-making: three ability-specific evaluators (Rally,
Seize, Last Stand) that each score their own opportunity using the MR4
preview functions, plus one shared "spend layer" (`chooseGeneralCommandAction`)
that compares whatever the evaluators found against the General's safety,
charges/cooldown state, and a difficulty-scaled eagerness weight, and either
issues the best one or does nothing this turn (falling back to a simple
defensive reposition). `processAIGeneralCommand` iterates a civ's Generals
and applies the chosen action; it is called twice per civ per AI round from
`processNonHumanMajorRound` — once *before* tactical-plan execution (Rally
heals/de-escalates supply and Last Stand braces a formation, both of which
should be active before this civ's own combat resolves and before the next
human/AI turn's incoming attacks), once *after* (Seize the Moment requires
`hasActed === true`, which only becomes true once this civ's tactical plan
has actually moved/attacked units). AI candidate-choice *acquisition* (which
of the 2-3 offered Generals to take) is a separate, much simpler concern —
a deterministic best-stat pick, added as a plain function in
`great-general-system.ts` and called directly from `turn-manager.ts`'s
existing per-civ round-end loop, requiring no new AI-module dependency and
no RNG.

**Tech Stack:** TypeScript, Vitest, vanilla DOM (no new dependencies).

## Global Constraints

- **No new RNG.** AI candidate-choice selection is a deterministic best-score
  sort (mirrors `generateGeneralCandidates`'s existing tie-break-by-id
  convention, just without the weighted-random draw stage). Ability
  evaluators are deterministic scores. If a step in this plan seems to need
  `Math.random()` or a new seeded draw, that's a signal of scope drift —
  stop and re-check against this constraint.
- **Difficulty alters judgment only (contract item 83).** Every eligibility
  check, threshold, and mechanic added or extended by this MR (candidate
  acquisition, ability eligibility, supply-aware withdrawal trigger) must be
  identical across `explorer`/`standard`/`veteran`. Only score *weights* feeding
  into which of several already-eligible actions gets chosen may read
  `OPPONENT_CHALLENGE_PROFILES`. Regression required (Task 10), extending
  MR3/MR4's `tests/systems/great-general-mr3-invariants.test.ts` /
  `great-general-mr4-invariants.test.ts` precedent with a new
  `great-general-mr5-invariants.test.ts`.
- **No hidden-info AI (contract item 84).** Any evaluator that looks at
  enemy units (Last Stand's "incoming threat" score) MUST filter through
  `getVisibility(civ.visibility, position) === 'visible'` — never scan
  `state.units` for enemy positions unfiltered. Mirrors `visibleThreatCount`'s
  existing pattern in `ai-tactics.ts`.
- **Architecture boundary.** `src/core/turn-manager.ts` never imports from
  `src/ai/*` (verified: its current import list is exclusively `@/systems/*`
  and `@/core/*`). AI decision logic for *which* candidate/ability to pick
  lives under `src/ai/*` or, where it's simple enough to be mechanical
  bookkeeping rather than a "decision" (candidate acquisition), as a plain
  exported function in `src/systems/great-general-system.ts` that
  `turn-manager.ts` can call directly.
- **Hot-seat privacy.** Every new function only ever touches
  `state.civilizations[civId].units`/`state.units[id]` for `civId`'s own
  units when writing, mirroring MR4's own hot-seat privacy test precedent
  (`great-general-mr4-invariants.test.ts`'s "only ever touches the issuing
  General's own owner civ").

```typescript
/**
 * #544 MR5: deterministic AI candidate pick among the 2-3 offered
 * `GeneralDefinition`s. No RNG (Global Constraints) -- a simple best-stat
 * sum, tie-broken by id for determinism. Difficulty-invariant: this never
 * reads `state.opponentChallenge` (contract item 83 -- candidate acquisition
 * is not a "judgment" call worth scaling, it's a one-time pick among
 * roughly-equal options).
 */
export function chooseBestGeneralCandidate(candidates: GeneralDefinition[]): GeneralDefinition {
  return [...candidates].sort((a, b) =>
    (b.commandRange + b.commandCapacity + b.maxCommandCharges)
    - (a.commandRange + a.commandCapacity + a.maxCommandCharges)
    || a.id.localeCompare(b.id))[0]!;
}
```

```typescript
    .filter(u => u.type === 'great_general' && u.generalDefinitionId)

 * civ can actually see (`getVisibility(...) === 'visible'`), never a raw

 * "in danger" -- the shared spend layer (Task 8) uses this to discourage
 * spending a scarce charge (or moving the General forward) while exposed.

    candidate.owner !== general.owner
```

```typescript
import { getHeroicCommandEligibility, getRallyPreview, issueRally } from '@/systems/great-general-abilities';

/**
 * contract §25: "Rally evaluator: missing HP, degradation cleanup, survival,
 * future usefulness." getRallyPreview already ranks/selects its own targets
 * by (missing HP + supply-stage severity) -- this evaluator's score is
 * simply the sum of each target's improvement, so a Rally that heals many
 * badly-hurt, badly-supplied units outscores one that barely helps a single
 * near-full-health unit. Returns null (not a zero-score opportunity) when
 * there is genuinely nothing to do, so the shared spend layer never has to
 * special-case "eligible but pointless."
 */
export function evaluateRallyOpportunity(state: GameState, generalUnitId: string): GeneralCommandOpportunity | null {
  const general = state.units[generalUnitId];
  if (!general) return null;
  const eligibility = getHeroicCommandEligibility(state, general);
  if (!eligibility.eligible) return null;

  const preview = getRallyPreview(state, generalUnitId);
  if (preview.targets.length === 0) return null;

  const score = preview.targets.reduce((sum, target) => {
    const healthGain = target.healthAfter - target.healthBefore;
    const stageRelief = target.stageBefore !== target.stageAfter ? 20 : 0;
    return sum + healthGain + stageRelief;
  }, 0);

  return { ability: 'rally', score, execute: s => issueRally(s, generalUnitId) };
}
```

```typescript
 * contract §25: "Seize evaluator: extra attack, kill potential,
 * capture/denial, reposition, breakthrough." A full kill-probability
 * simulation is out of scope for v1 (YAGNI) -- combat-capable acted units
 * get a flat high per-unit value (an extra attack from a real attacker is
 * almost always worth a charge), non-combat acted units (already-moved
 * workers/settlers/etc, repositioning value only) get a much smaller flat

export function evaluateSeizeOpportunity(state: GameState, generalUnitId: string): GeneralCommandOpportunity | null {

    const unit = state.units[entry.unitId];
    return sum + (unit && hasAICombatRole(unit.type) ? SEIZE_COMBAT_UNIT_VALUE : SEIZE_NONCOMBAT_UNIT_VALUE);
  }, 0);

  return {
    ability: 'seize_the_moment',
    score,
    execute: s => issueSeizeTheMoment(s, generalUnitId, eligible.map(e => e.unitId)),
```

```typescript
import { getEffectiveCommandStats } from '@/systems/great-general-system';
import { GENERAL_DEFINITIONS as GENERAL_DEFS_FOR_LAST_STAND } from '@/systems/great-general-definitions'; // reuse existing import if already present above, do not double-import
import { getLastStandPreview, issueLastStand } from '@/systems/great-general-abilities';

const LAST_STAND_THREAT_SCAN_RADIUS = 2;

function nearbyVisibleThreatScore(state: GameState, civId: string, hex: { q: number; r: number }): number {
  const visibility = state.civilizations[civId]?.visibility;
  if (!visibility) return 0;
  return Object.values(state.units).filter(candidate =>
    candidate.owner !== civId
    && isAIHostileOwner(state, civId, candidate.owner)
    && getVisibility(visibility, candidate.position) === 'visible'
    && mapDistance(state.map, hex, candidate.position) <= LAST_STAND_THREAT_SCAN_RADIUS,
  ).length;
}

/**
 * contract §25: "Last Stand evaluator: strategic position, incoming threat,
 * value of units, expected Hold save value, city/Fort/Citadel/chokepoint
 * defense." Candidate hexes are every distinct position occupied by one of
 * the General's own eligible units within commandRange (Last Stand's own
 * area is centered on a hex, not a specific unit -- see
 * getLastStandPreview) -- for each, score = (own unit count at/near that
 * hex, from the preview's own targets) * threat at that hex (fog-of-war-safe
 * per contract item 84). A hex with a real formation under real incoming
 * threat outscores an empty or safe one; ties broken by hex key for
 * determinism.
 */
export function evaluateLastStandOpportunity(state: GameState, generalUnitId: string): GeneralCommandOpportunity | null {
  const general = state.units[generalUnitId];
  if (!general) return null;
  const eligibility = getHeroicCommandEligibility(state, general);
  if (!eligibility.eligible) return null;
  const definition = GENERAL_DEFINITIONS.find(g => g.id === general.generalDefinitionId);
  const civ = state.civilizations[general.owner];
  if (!definition || !civ) return null;
  const { commandRange } = getEffectiveCommandStats(general, definition);

  const candidateHexes = civ.units
    .map(id => state.units[id])
    .filter((u): u is Unit => Boolean(u))
    .filter(u => u.id !== general.id)
    .filter(u => mapDistance(state.map, general.position, u.position) <= commandRange)
    .map(u => u.position);

  let best: { hex: { q: number; r: number }; score: number } | null = null;
  for (const hex of candidateHexes) {
    const preview = getLastStandPreview(state, generalUnitId, hex);
    if (preview.targets.length === 0) continue;
    const score = preview.targets.length * (1 + nearbyVisibleThreatScore(state, general.owner, hex));
    if (!best || score > best.score
      || (score === best.score && `${hex.q},${hex.r}`.localeCompare(`${best.hex.q},${best.hex.r}`) < 0)) {
      best = { hex, score };
    }
  }
  if (!best) return null;

  return {
    ability: 'last_stand',
    score: best.score,
    execute: s => issueLastStand(s, generalUnitId, best!.hex),
  };
}
```

```typescript
 * contract §25 "shared layer considers: charges left, cooldown, General
 * safety, objective importance, tactical swing." Charges/cooldown are
 * already the eligibility gate each evaluator checks via
 * getHeroicCommandEligibility (an ineligible ability simply returns null
 * and is never a candidate here -- this function only ever compares
 * opportunities that already passed that gate, so "charges left"/"cooldown"
 * are satisfied structurally, not by extra logic in this function).
 * "General safety" is applied here as a flat score penalty (scaled by
 * profile.generalSafetyWeight) when isGeneralInDanger is true -- discourages
 * (but does not forbid) spending a charge while exposed, rather than
 * hard-blocking it, since sometimes using the charge anyway (e.g. Last
 * Stand to brace against the very threat endangering the General) is
 * correct. "Objective importance"/"tactical swing" are represented by each
 * evaluator's own score (Rally's healing total, Seize's unit-value sum,
 * Last Stand's formation-size*threat product) -- this function's only job
 * is comparing those already-computed scores, weighted by difficulty
 * eagerness, and picking the best.
 */
export function chooseGeneralCommandAction(state: GameState, generalUnitId: string): GeneralCommandOpportunity | null {
  const general = state.units[generalUnitId];
  if (!general) return null;
  const profile = OPPONENT_CHALLENGE_PROFILES[resolveOpponentChallenge(state)];
  const dangerPenalty = isGeneralInDanger(state, general)
    ? GENERAL_DANGER_SCORE_PENALTY * profile.generalSafetyWeight
    : 0;

  const opportunities = [
    evaluateRallyOpportunity(state, generalUnitId),
    evaluateSeizeOpportunity(state, generalUnitId),
    evaluateLastStandOpportunity(state, generalUnitId),
  ].filter((o): o is GeneralCommandOpportunity => o !== null);
  if (opportunities.length === 0) return null;

  const scored = opportunities
    .map(o => ({ opportunity: o, adjustedScore: o.score * profile.heroicCommandEagernessWeight - dangerPenalty }))
    .sort((a, b) => b.adjustedScore - a.adjustedScore || a.opportunity.ability.localeCompare(b.opportunity.ability));

  const winner = scored[0]!;
  return winner.adjustedScore > 0 ? winner.opportunity : null;
}

/**
 * Per-civ dispatch entry (Task 9 calls this twice per round). 'pre-tactical'
 * runs Rally and Last Stand (both should be active before this civ's own
 * combat and before the next turn's incoming attacks); 'post-tactical' runs
 * only Seize the Moment (requires hasActed units, which only exist after
 * this civ's tactical plan has actually moved/attacked). A General that
 * issues nothing this phase is left in place -- MR5 does not add General
 * repositioning beyond what its own eligible-target search already implies;
 * a General with nothing useful to do simply holds, matching how
 * `great_general`'s civilian classification already leaves it alone in the
 * plan/role tactical system (see this plan's drift finding #3).
 */
export function processAIGeneralCommand(
  state: GameState,
  civId: string,
  phase: 'pre-tactical' | 'post-tactical',
): GameState {
  let working = state;
  for (const general of getEraGenerals(working, civId)) {
    const chosen = chooseGeneralCommandAction(working, general.id);
    if (!chosen) continue;
    if (phase === 'pre-tactical' && chosen.ability === 'seize_the_moment') continue;
    if (phase === 'post-tactical' && chosen.ability !== 'seize_the_moment') continue;
    working = chosen.execute(working);
  }
  return working;
}
```
