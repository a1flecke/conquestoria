# MR 1 — #1064 AI baseline expansion / production viability

## Behaviour and non-goals

**Behaviour.** A viable low-city AI civ generates `expand` objective candidates from
fog-bounded known terrain. With no settler it emits a bounded `settlement` readiness
demand, so `generateAIProductionCandidates` surfaces a settler. With a settler, the
candidate becomes a real plan, the settler is assigned, dispatched, moved toward the
site and founds a city. AI civs expand over long campaigns; cities stop idling for
dozens of rounds; gold stops accumulating unspent.

**Non-goals.** No settler spam. No erasure of the value of strategic plans. No
convergence of personalities onto identical behaviour. No difficulty change to core
legality. No `worker` demand. No #1066 production cap. No #1069 caching layer.

## APIs and contracts

New module `src/ai/ai-expansion-sites.ts` — pure, no state mutation, no RNG:

```ts
export interface AIExpansionSite {
  anchor: HexCoord;
  score: number;          // evaluateExpansionTarget over the known neighbourhood
}

/** Fog-bounded candidate founding sites, best first, then hexKey ascending. */
export function getKnownExpansionSites(
  knownMap: GameMap,                       // from buildKnownPathMap(state, civId)
  knownCityPositions: readonly HexCoord[], // from perception.knownCities (position !== null)
  anchors: readonly HexCoord[],            // operational anchors (own cities, else own units)
  limit: number,
): AIExpansionSite[];

export const EXPAND_CANDIDATE_LIMIT = 3;
export const EXPANSION_CITY_SOFT_CAP_BASE = 2;

/** Owned-city count at or above which no expand candidate is produced. Range 2..6. */
export function getExpansionCitySoftCap(expansionDrive: number): number {
  return EXPANSION_CITY_SOFT_CAP_BASE + Math.round(expansionDrive * 4);
}
```

`getKnownExpansionSites` never reads `GameState`. It receives the already-fog-bounded
map, so information safety is structural, not a convention. It is pure geometry: it
knows nothing about personality or city counts. **The soft cap is applied by the
caller** (`expandCandidates()` in `ai-prepared-turn.ts`), which is the only place that
holds both `perception.ownCities.length` and the personality.

`objectiveCandidates()` (`ai-prepared-turn.ts:218`) does **not** currently receive a
`PersonalityTraits`. It receives `doctrine`, which `prepareMajorCivStrategicPlan` built
from `resolveCivDefinition(state, civ.civType)?.personality`. Thread the personality
through as an explicit parameter — do **not** re-resolve the civ definition inside
`objectiveCandidates`, and do **not** widen `DominationDoctrine` to smuggle it.

## TDD order

### Task 1 — site enumeration (`ai-expansion-sites.ts`)

**Tests first** (`tests/ai/ai-expansion-sites.test.ts`):

*Positive*
- returns a legal land site outside `MIN_CITY_CENTER_DISTANCE` of every known city
- orders by score descending, then `hexKey` ascending (deterministic total order)
- respects `limit`
- prefers a grassland/plains neighbourhood over a desert/tundra one (via
  `evaluateExpansionTarget`)

*Negative*
- never returns `ocean` / `coast` / `mountain`
- never returns a tile within `MIN_CITY_CENTER_DISTANCE` of a **known** city
- **never returns a tile absent from the known map**, even when that tile is
  objectively the best site (the information-safety proof)
- returns `[]` when no anchor exists
- returns `[]` when no legal site exists

**Then implement.** Pure function over `knownMap.tiles`. No `state`, no RNG, no
`Math.random()`.

### Task 2 — expand candidates in `objectiveCandidates()`

**Tests first** (`tests/ai/ai-prepared-turn.test.ts`):

*Positive*
- a one-city civ at peace with a known legal site produces an `expand` candidate with
  `requiredRoles: { settlement: 1 }` and target `{ kind: 'region', id: 'settle:<q>,<r>' }`
- with **no** settler, `prepareMajorCivStrategicPlan(...).forceDemands` contains

- with a settler already **queued**, `missing === 0` (`residualDemands` path)
- expand candidate count never exceeds `EXPAND_CANDIDATE_LIMIT`
- **the total analysed candidate count in the `objective` trace stays ≤ 12** — pin this

**Then implement.** Insert an `expandCandidates()` block into `objectiveCandidates()`
alongside the existing capture and resource blocks. Feed candidates through the same
`resolveObjectiveTravelCandidates` path. `strategicValue` derives from the site score,
scaled by `expansionDrive`; `expectedLossRatio: 0`; `explicitDistantReasons: []`
(expansion is a local activity — it must not earn the +35 distant-reason bonus).

## Step 3 — caching rules (non-negotiable)

- Transient; rebuilt from state every round.
- **Never persisted** — no new `GameState` field, no save impact.
- Never crosses a mutation boundary carrying stale derived data.
- Cache keys encode **every** input that affects the result.
- No hidden-information widening.
- No changed tie-breaking, no changed iteration order, no nondeterministic
  `Map`/`Set` dependence that affects results.

# Cross-arc constraints

**Determinism.** Same seed + same commands/state stays deterministic. Trace ordering
and tie-breaking preserved. Compare states only via `assertSimulationEquivalent` /
`firstSimulationDivergence`.

**Save compatibility.** No `SAVE_VERSION` bump unless a real persisted-shape change
becomes unavoidable. None is expected in any MR. If one becomes unavoidable, stop and
escalate — it changes the MR's risk class.

**Hot seat.** No behaviour depends on `currentPlayer` for authoritative AI simulation.
Viewer-private presentation stays viewer-scoped. `lh-hotseat-medium` in every matrix run.

**Difficulty.** Explorer / Standard / Veteran tune scores and thresholds through
existing challenge profiles only. Core legality and state integrity stay common.

**Ages / UX.** Players aged 7–43 meet a more credible opponent, not a more opaque one.
No player-facing complexity added.

**Performance.** A lower operation count is not automatically good — always
cross-check AI quality.

**Architecture.** Use existing canonical APIs and seams. No parallel executors, no
hidden state-mutation paths, no new ad-hoc caching framework where a seam exists.

**Tests.** Focused first; integration once behaviour stabilizes; one full durable pass
near completion; long-horizon whenever AI behaviour changes; perf suite for MR3.

**MR size.** One issue per MR. Never combine #1064 + #1066 + #1069.
