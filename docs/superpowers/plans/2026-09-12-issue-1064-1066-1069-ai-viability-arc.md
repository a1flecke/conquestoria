# MR 1 — #1064 AI baseline expansion / production viability

## Behaviour and non-goals

**Behaviour.** A viable low-city AI civ generates `expand` objective candidates from
fog-bounded known terrain. With no settler it emits a bounded `settlement` readiness
demand, so `generateAIProductionCandidates` surfaces a settler. With a settler, the
candidate becomes a real plan, the settler is assigned, dispatched, moved toward the
site and founds a city. AI civs expand over long campaigns; cities stop idling for
dozens of rounds; gold stops accumulating unspent.

A bounded `worker` demand ships alongside, because workers have the production gap but
**not** the execution gap (`basic-ai.ts:700` already tasks them), and because expansion
alone does not clear `production-idle` / `gold-hoard` for a developed civ — see design
§2.12 and the §2.19 contingency.

**Non-goals.** No settler spam. No erasure of the value of strategic plans. No
convergence of personalities onto identical behaviour. No difficulty change to core
legality. No change to worker *task* selection. No richer site valuation (resources,
rivers, coast, chokepoints). No #1066 production cap. No #1069 caching layer.

## APIs and contracts

### `src/systems/city-territory-system.ts` — one new pure export

```ts
/** May a city centre stand on this terrain? The single definition of that rule. */
export function isCityCenterTerrain(terrain: TerrainType): boolean;
```

The private `isValidCityCenterTerrain` (line 483) is rewritten to call it, and
`ai-resettlement.ts`'s local `isFoundingTerrain` (line 17) is deleted in favour of it.
Leave `barbarian-system.ts:222` and `rogue-elephant-host-system.ts:81,158` alone —
they mean "a land actor may spawn here", which merely coincides today.

### `src/ai/ai-expansion-sites.ts` — new, pure, `GameState`-free

```ts
export interface AIExpansionSite {
  anchor: HexCoord;
  /** evaluateExpansionTarget over the site's known neighbourhood. */
  score: number;
}

export const EXPANSION_SEARCH_RADIUS = 8;
export const EXPANSION_SITE_SHORTLIST = 3;
export const EXPANSION_CITY_SOFT_CAP_BASE = 2;
export const WORKER_SOFT_CAP = 4;

/** Owned-city count at or above which no expand candidate is produced. Range 2..6. */
export function getExpansionCitySoftCap(expansionDrive: number): number {
  return EXPANSION_CITY_SOFT_CAP_BASE + Math.round(expansionDrive * 4);
}

/**
 * Sites this civ BELIEVES a city could stand on, best first then hexKey ascending.
 * `knownMap` must already be fog-bounded (buildKnownPathMap); this function performs
 * no visibility filtering of its own and never sees the real state.
 */
export function getKnownExpansionSites(
  knownMap: GameMap,
  knownCityPositions: readonly HexCoord[],
  anchors: readonly HexCoord[],
  limit: number,
): AIExpansionSite[];
```

**Purity is the contract.** The module must not import `GameState`. A pure function over
an already-fog-bounded map cannot leak hidden information even if a future author is
careless, because the omniscient state is not in scope to read — information safety by
construction rather than by review vigilance. Enforce it with an explicit assertion in
`tests/ai/ai-expansion-sites.test.ts` that the module source contains no `GameState`
reference, alongside the behavioural negative test.

It is **pure geometry**: it knows nothing about personality or city counts. The soft cap
is applied by the caller.

### `src/ai/ai-prepared-turn.ts` — one shared demand-seed helper

```ts
/**
 * An incremental demand: "one more R, up to `cap`".
 * desired = min(owned + 1, cap); assigned = owned; so missing is always 0 or 1.
 * Returns [] when already at cap, so callers need no branch of their own.
 */
function incrementalDemandSeed(
  role: AIStrategicRole,
  sourceId: string,
  priority: number,
  owned: number,
  cap: number,
): PreparedForceDemandSeed[];
```

Every incremental demand goes through this. Two callers in MR1:

| Demand | `owned` | `cap` | Priority |
|---|---|---|---:|
| `objective-readiness` (any role, incl. `settlement`) | `Math.min(availableRoles[role] ?? 0, 1)` | `1` | 90 |
| `worker` | live worker count | `Math.min(ownCityCount, WORKER_SOFT_CAP)` | 40 |

`settlement` needs **no dedicated seed** — it rides the readiness path because the
`expand` candidate declares `requiredRoles: { settlement: 1 }`.

`objectiveCandidates()` (`ai-prepared-turn.ts:218`) does **not** currently receive a
`PersonalityTraits`. It receives `doctrine`, which `prepareMajorCivStrategicPlan` built
from `resolveCivDefinition(state, civ.civType)?.personality`. Thread the personality
through as an explicit parameter — do **not** re-resolve the civ definition inside
`objectiveCandidates`, and do **not** widen `DominationDoctrine` to smuggle it.

### Task 1 — site enumeration (`ai-expansion-sites.ts`)

**Tests first** (`tests/ai/ai-expansion-sites.test.ts`):

*Positive*
- returns a legal land site outside `MIN_CITY_CENTER_DISTANCE` of every known city
- orders by score descending, then `hexKey` ascending (deterministic total order)
- respects `limit`
- prefers a grassland/plains neighbourhood over a desert/tundra one (via
  `evaluateExpansionTarget`)
- **wrapping map**: on a `wrapsHorizontally` map, a site near the seam that is within
  `MIN_CITY_CENTER_DISTANCE` of a known city **across the seam** is rejected. This is
  the test that fails if someone reaches for `hexDistance` instead of `cityDistance`
- `getExpansionCitySoftCap` is monotonic in `expansionDrive`, returning 2 at `0` and 6
  at `1`

*Negative*
- never returns a tile failing `isCityCenterTerrain`
- never returns a tile within `MIN_CITY_CENTER_DISTANCE` of a **known** city
- **never returns a tile absent from the known map**, even when that tile is objectively
  the best site — the information-safety proof
- never returns a tile beyond `EXPANSION_SEARCH_RADIUS` of every anchor
- returns `[]` when no anchor exists
- returns `[]` when no legal site exists

*Structural*
- the module source contains no `GameState` reference (read the file and assert) —
  purity is the contract, not a convention

**Then implement.** Pure function over `knownMap.tiles`. Import
`isCityCenterTerrain`, `MIN_CITY_CENTER_DISTANCE`, `cityDistance` and
`canonicalizeCityCoord` from `city-territory-system.ts`; do not re-derive any of them.
Bound the scan to `EXPANSION_SEARCH_RADIUS` around each anchor — this is a cost bound,
not flavour: an unbounded scan is `O(known tiles x known cities)` per civ per round,
which would add a new super-linear cost inside the arc that exists to remove one.
No `state`, no RNG, no `Math.random()`.

### Task 4 — expand candidates in `objectiveCandidates()`

**Tests first** (`tests/ai/ai-prepared-turn.test.ts`):

*Positive*

hidden state-mutation paths, no new ad-hoc caching framework where a seam exists.

near completion; long-horizon whenever AI behaviour changes; perf suite for MR3.
